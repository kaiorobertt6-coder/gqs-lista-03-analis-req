# Gota6 – Monitoramento Inteligente de Água

## Sobre o Projeto

O **Gota6** é um projeto desenvolvido para a disciplina de **Gestão e Qualidade de Software**, com o objetivo de realizar o levantamento, análise e especificação dos requisitos de um sistema de monitoramento inteligente do consumo de água residencial.

O projeto propõe um aplicativo capaz de registrar leituras de hidrômetro, utilizando tanto o preenchimento manual quanto a tecnologia OCR, calcular o consumo de água e apresentar informações que auxiliem o usuário na identificação de possíveis desperdícios.

---

###  Documento de Especificação – Word

Este arquivo apresenta a **especificação detalhada dos requisitos do Gota6** e tem como finalidade documentar as características, regras e critérios de qualidade definidos para o sistema.

O documento contém:

* **Visão Geral do Sistema:** apresenta o objetivo, escopo e público-alvo do Gota6;
* **Matriz de Requisitos:** apresenta os Requisitos Funcionais (RF) e Requisitos Não Funcionais (RNF), suas prioridades e critérios de aceite;
* **Modelagem de Dados e Arquitetura:** apresenta a estrutura proposta para as entidades `Usuario` e `Historico`, além do relacionamento entre elas e o modelo de classes;
* **Estratégia de Versionamento e Qualidade:** define as práticas de utilização do GitHub, branches, commits, Code Review e CI/CD;
* **Plano de Garantia da Qualidade (QA):** apresenta cenários de teste para validar as principais funcionalidades do sistema;
* **Conclusão:** reúne os principais resultados da especificação do projeto.

O documento tem como finalidade servir como **base de referência para uma futura implementação do sistema**, deixando definidos os requisitos e critérios que deverão ser considerados durante o desenvolvimento.

Este arquivo tem como finalidade **apresentar de forma resumida e visual os principais pontos da especificação do Gota6**.

A apresentação foi estruturada para uma apresentação técnica aos stakeholders e contém:

2. Problema e escopo da solução;

4. Requisitos não funcionais e metas de qualidade;

7. Estratégia de versionamento e Code Review;

A apresentação tem como finalidade **comunicar de maneira objetiva os requisitos, a arquitetura proposta e a estratégia de qualidade do projeto**, complementando o documento de especificação.
